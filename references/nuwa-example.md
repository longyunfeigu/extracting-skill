# 示例：拆解 nuwa-skill

这个示例是语气标尺：保留流程、文件结构和可复用招式，但不要写成抽象分析报告。

## Skill：女娲造人

### 这个 skill 为什么让人眼前一亮

它不是让 AI “模仿某个人说话”，也不是写一堆名人金句。

它做的是一条生产线：

```text
输入一个人名或模糊需求
→ 从多个角度研究这个人
→ 把漂亮观点筛成真正能用的心智模型
→ 做成一个完整 skill 包
→ 测试这个 skill 遇到新问题时是不是真的有用
```

厉害的地方不是“像不像某个人”，而是它试图把一个人的判断方式做成可运行的工具。

### 它在防什么坏结果

它在防“假人物 skill”。

这种坏 skill 通常长这样：

- 几句名人语录
- 一点表面语气模仿
- 很自信地说“如果我是某某，我会……”
- 不区分一手资料和二手总结
- 不写局限
- 不证明这个视角能处理新问题

看起来像角色，其实只是换了衣服的通用 AI。

### 它为什么要这样设计

因为只看一个来源，理解不了一个人。

书和长文能看到系统思想。访谈能看到临场反应。社交媒体能看到语言习惯。别人怎么批评他，能看到盲点。重大决策能看到他说的和做的是不是一致。时间线能看到他的想法有没有变。

所以它才要分很多路调研。这个流程很重，但它要避免的是廉价模仿。

### 先把关键概念讲清楚

| 概念 | 人话解释 | 怎么判断 | 小例子 |
| --- | --- | --- | --- |
| 心智模型 | 不是“这个人说过什么”，而是他反复用来判断问题的看法。 | 换一个新问题，这个看法还能推出一个判断。 | 芒格的“逆向思考”：不管是投资、人生还是产品，他都会先问“怎样会失败”。 |
| 决策启发式 | 做判断时的快捷规则，像“遇到这种情况，先这样处理”。 | 它通常能写成“如果 X，就先做 Y”。 | “先放进 Too Hard 筐”：看不懂的投资先不碰，不硬猜。 |
| 表达 DNA | 这个人说话和写作的习惯，不只是语气，还包括节奏、用词、类比方式和确定性。 | 删掉名字后，读一段回答还能感觉像这个人。 | MrBeast 会直接问 CTR、AVD、前 30 秒留存，而不是泛泛说“内容要吸引人”。 |
| 诚实边界 | skill 主动承认自己不知道什么、哪里只是推断、信息截止到什么时候。 | 它具体写出不能做什么，而不是只说“仅供参考”。 | 活人 skill 要写清楚：公开表达不等于真实想法，近期变化需要重新查。 |
| Agentic Protocol | skill 自带的一段行动流程，告诉 AI 遇到不同问题该先查资料、先分类，还是直接回答。 | 它不是知识点，而是“收到问题后先做什么”的步骤。 | 人物 skill 遇到“现在这家公司值不值得投”时，先查最新数据，再套人物框架判断。 |

### 它逼 AI 先做什么

- 先建 skill 目录，让后续资料有地方放。
- 把调研材料存进 `references/research/`，不要散落在外面。
- 区分一手资料、二手资料和自己的推断。
- 在提炼前，先给用户看调研质量。
- 在写最终 skill 前，先给用户看提炼方向。
- 生成后，用已知问题、边界问题、表达风格问题测试一遍。

### 它不让 AI 怎么偷懒

- 不准只靠名人语录做人设。
- 不准把矛盾抹平。
- 不准把弱来源当强来源。
- 不准资料不足还装完整。
- 不准遇到事实问题还凭旧知识回答。
- 不准交付一个没有诚实边界的 skill。

### 它是怎么跑起来的

1. **入口分流**：用户说清楚了要蒸馏谁，就进入直接路径；用户只有模糊需求，就先诊断需求，再推荐候选人物或主题。
2. **确认目标**：确认人物、用途、聚焦方向，以及用户有没有本地一手材料。
3. **创建 skill 包**：建好 `SKILL.md`、`references/research/`、`sources/`、`scripts/`。
4. **六路调研**：著作、对话、表达、他者评价、重大决策、时间线。
5. **调研验收**：暂停，展示来源数量、关键发现、矛盾点和薄弱维度。
6. **提炼思维方式**：提取心智模型、决策规则、表达 DNA、价值观、反模式和诚实边界。
7. **提炼验收**：让用户确认这些模型有没有抓对重点。
8. **生成 skill**：套模板写出最终 `SKILL.md`，并加上“什么时候要先查资料再回答”的工作流。
9. **质量验证**：用已知立场、未知边界题和风格题测试。
10. **二次精炼**：再从触发条件、可操作性、边界处理上做 review。
11. **后续更新**：如果人物有新动态，不重写整个 skill，只更新受影响的部分。

### 用一个例子跑完整流程

**例子输入：** “帮我蒸馏一个乔布斯 skill，用来审视产品设计和战略取舍。”

| 阶段 | 这一阶段拿到什么 | AI 要做什么 | 这一阶段产出什么 | 你能学到哪招 |
| --- | --- | --- | --- | --- |
| 入口分流 | 用户明确说“乔布斯 skill” | 判断这是明确人物，不需要先推荐候选 | 进入直接蒸馏路径 | 先分流，别所有请求都走同一套问答 |
| 需求确认 | 人物=乔布斯；用途=产品设计/战略取舍 | 确认是否全面画像、是否有本地素材、是新建还是更新 | 目标变成“乔布斯视角的产品/战略顾问” | 先定用途，后面才知道该重读哪些材料 |
| 创建目录 | 已确认要新建 skill | 创建 `steve-jobs-perspective/`，里面放 `SKILL.md`、`references/research/`、`sources/`、`scripts/` | 一个自包含 skill 包骨架 | 先建容器，防止调研材料散掉 |
| 六路调研 | 需要理解乔布斯如何判断产品 | 分别研究著作/演讲、长访谈、表达风格、外部批评、重大决策、时间线 | `01-writings.md` 到 `06-timeline.md` | 不从一个来源总结一个人 |
| 调研检查点 | 六份调研文件 | 汇总来源数量、关键发现、矛盾点、薄弱维度 | 一张调研质量表 | 先判断材料够不够，再开始提炼 |
| 三重验证 | 一堆候选观点，例如“聚焦”“端到端控制”“现实扭曲力场” | 问每个观点：是否跨场景出现？能否判断新问题？是否有独特性？ | 3-7 个核心心智模型；较浅的降级为启发式 | 不把漂亮话直接升格成核心模型 |
| 提炼检查点 | 心智模型、启发式、表达 DNA、张力草稿 | 展示给用户确认：有没有抓错重点？有没有缺关键模型？ | 被确认或修正的提炼方向 | 在主观判断最重的地方停一下 |
| 生成 skill | 已确认的提炼结果 + `skill-template.md` | 写出最终 `SKILL.md`：角色规则、身份卡、模型、启发式、表达 DNA、边界、来源 | 可安装的 `steve-jobs-perspective/SKILL.md` | 模板不是偷懒，是保证结构不漏 |
| 加 Agentic Protocol | 乔布斯模型强调产品体验、端到端控制、市场时机 | 推导研究维度：看产品体验、设计细节、技术路线、市场时机 | skill 遇到 Vision Pro 这类问题会先查资料 | 让成品 skill 不只“说得像”，还“做得像” |
| 质量验证 | 最终 `SKILL.md` | 用已知问题、边界问题、100 字风格测试检查 | 通过/失败项，必要时回到提炼阶段修 | 生成不是结束，验证才是交付前的门 |

### 它把东西放在哪里

- `SKILL.md`：整条生产线，从入口分流到验证交付。
- `references/extraction-framework.md`：怎么判断一个观点是不是心智模型。
- `references/skill-template.md`：最终人物 skill 的标准骨架。
- `scripts/`：字幕清洗、调研摘要、质量检查这些容易出错的重复工作。
- `examples/`：已经做好的成品人物/主题 skill。
- 生成出来的新 skill 目录：最终 `SKILL.md`、调研笔记、原始材料和脚本都放在一起。

### 我能偷走哪几招

1. **思维操作系统**：不要做“像某个人说话”，要做“用某个人的判断方式工作”。
2. **六路取证**：从著作、对话、表达、他者评价、决策、时间线六个角度理解对象。
3. **三关筛选**：一个观点要变成心智模型，必须反复出现、能推断新问题、还有独特性。
4. **先查再答**：人物视角遇到当前事实问题时，先查资料，再用人物模型判断。
5. **中途验收**：调研后验收一次，提炼后再验收一次，别等写完才发现方向错了。
6. **自包含 skill 包**：指令、证据、来源、脚本都在 skill 目录里，复制走也能用。

### 哪些地方太重

如果只是想要一个临时角色扮演 prompt，这套流程太重。

它适合做长期会复用、会分享、会依赖判断质量的 skill。它不适合十分钟写完的玩具 prompt。

它还有一个工具层面的提醒：本地测试时，验证脚本在 Python 3.7 下跑不起来，因为用了较新的类型标注语法。只要 skill 依赖脚本，就要写清楚运行环境，或者把脚本写得更兼容。

## 模式卡

### 思维操作系统

**它防的是：** 只会模仿语气和拼贴语录的人物 skill。

**适合用在：** 你要做一个专家视角、导师视角、人物视角，而不是单纯角色扮演。

**怎么做：** 同时提取心智模型、决策规则、表达风格、反对什么、做不到什么。

**通常放在：** 最终 `SKILL.md`，证据放在 `references/`。

**代价：** 需要更多调研和提炼，比普通 prompt 慢很多。

**适合搭配：** 三关筛选、诚实边界、先查再答。

**例子：** `nuwa-skill` 把这个作为所有人物 skill 的目标形态。

### 六路取证

**它防的是：** 从一个方便来源就开始总结一个人。

**适合用在：** skill 依赖对某个人、领域或方法论的深度理解。

**怎么做：** 把研究拆成几个能看到不同真相的维度。

**通常放在：** `references/research/`。

**代价：** 慢、耗上下文、需要协调多个研究结果。

**适合搭配：** 中途验收、来源质量分层。

**例子：** `nuwa-skill` 拆成著作、对话、表达、他者评价、决策、时间线。

### 三关筛选

**它防的是：** 把每句好听的话都升级成心智模型。

**适合用在：** 需要决定哪些想法值得写进 skill 核心。

**怎么做：** 问三个问题：它有没有跨场景反复出现？能不能推断新问题？是不是有独特视角？

**通常放在：** `references/extraction-framework.md` 或 `SKILL.md` 的提炼流程里。

**代价：** 有些有用但不够深的东西会被降级成启发式。

**适合搭配：** 思维操作系统、诚实边界。

**例子：** `nuwa-skill` 用它区分“核心心智模型”和“决策启发式”。
